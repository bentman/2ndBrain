# Knowledge

Use this when research, a lesson, or an explanation is worth reusing.

## Route

- Reusable beyond one project -> `_user/[domain]/knowledge/`
- Only matters to one project -> that project's `research.md` or `notes.md`
- One-off answer -> answer directly; no file unless asked

## Write

1. Search the domain for an existing note. Update it if one exists.
2. One idea per note. Make the title state the idea ("Retries need jitter", not "Retry notes").
3. Start with a one-line `Summary:`.
4. Capture findings, not raw source material. Link out rather than copying documentation.
5. Record sources and open questions.
6. Link to related notes and projects. Add a link back from at least one of them.
7. Follow Ingest in `AGENTS.md` (index line, log line).

Use `_system/templates/note.md` when structure helps. Skip sections that do not apply.

## Maintain

- When a note is reused, improve it: tighten the summary, fix what is stale, add the new example.
- When a note grows a second idea, split it and link the two.
- When several notes cover one topic, add a topic subfolder or a short overview note that links them. Not before.

## Rule

A few well-linked notes beat many isolated ones. Do not clutter `knowledge/` with one-off answers.
